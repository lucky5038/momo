Momo传值助手
工具作用、研发过程与产品价值说明

版本：2.2.59（全新安装引导修复）
日期：2026-10-28


一、工具真正的作用

Momo传值助手不是一个普通的网页，也不只是一个批量执行 UPDATE 的小工具。

它本质上是一个面向 ERP 数据库的业务数据映射与自动联动工具，由以下能力组成：

1. ERP 元数据识别
2. 单据头身关系识别
3. 来源代码与业务链路推导
4. 字段映射与 SQL 自动生成
5. 数据库更新执行
6. 数据库触发器生成与增量合并
7. 备份、回滚和字段安全校验

它解决的问题是：

当 ERP 的单据之间需要自动带值、补值、覆盖或合并值时，减少实施人员手工找表、找字段、判断来源关系、编写 SQL、编写触发器和反复验证的工作。


二、传统 ERP 传值方式的主要问题

传统方式通常依赖人工处理：

1. 在数据库中逐张表查找目标单头和单身。
2. 查找来源单号和序号字段。
3. 判断供应商、客户、品号、序号等关联维度。
4. 判断检验、免检、退货、委外等不同业务分支。
5. 手工编写 SQL 或触发器。
6. 多个字段分别建触发器。
7. 修改后容易覆盖旧逻辑。
8. 缺少预览、字段校验和重复值保护。
9. 出现数据库版本或账套变化时，需要重新配置。

人工方式高度依赖实施经验，容易产生重复取值、错误关联、触发器冲突和历史数据被误覆盖等问题。


三、研发过程

1. 读取数据库结构

工具读取 SQL Server 的系统表、字段和扩展说明，包括：

- 表名
- 字段名
- 字段说明
- 主键
- 单号列
- 序号列
- 品号列
- 供应商和客户维度

2. 识别单据结构

工具将 ERP 表识别为单头、单身和来源档，并识别：

- 前置来源
- 前置单号
- 前置序号
- 来源
- 来源单号
- 来源序号

3. 建立业务链路图

工具扫描全库来源字段，将来源代码与候选单据关联，建立有向业务链路图。

已实现：

- 来源代码固定映射
- 数据驱动候选匹配
- 候选类型字段验证
- 跨多张单据的代码族共识
- 非标准字段适配器

4. 查找路径

工具使用 BFS 查找目标单据与来源档之间的有效路径。

支持：

- 单跳直连
- 多跳链路
- 单头到单身
- 单身到单头
- 多路径业务分支

5. 多路径去重

同一目标行可能同时被多条链命中。

工具使用目标单号和序号进行行级优先级选择，避免：

- 预览重复
- 强制覆盖重复执行
- 同一目标字段被多个来源反复覆盖

6. SQL 生成

根据目标单据、目标字段、来源档和来源字段，工具自动生成：

- 预览 SQL
- 更新 SQL
- 行数统计 SQL
- 触发器更新 SQL

支持模式：

- 只填空
- 纠正错值
- 强制覆盖
- 合并显示

7. 触发器生成

工具为每个目标表生成统一触发器：

trg_<单据表>_momo

触发器特点：

- AFTER INSERT
- 只处理本次新增行
- 默认只填空
- 支持多字段
- 自动合并已有工具触发器
- 同一目标字段可替换或追加
- 使用 XACT_ABORT ON

8. 安全措施

- 执行前预览
- 执行前字段存在性校验
- 重复目标字段拦截
- 多路径行级去重
- 数据库事务
- 数据库备份
- 触发器创建后复核
- 服务只监听 127.0.0.1
- 测试触发器创建后删除


四、传值功能如何实现

普通传值的核心逻辑是：

目标单据单身
JOIN 来源单据单身
JOIN 必要的中间业务单据
SET 目标字段 = 来源字段

实际实现会同时处理：

- 来源代码互斥
- 单号匹配
- 序号匹配
- 品号维度
- 供应商或客户维度
- 单头与单身转换
- 检验与其他业务分支
- 多字段映射
- 重复值保护

触发器使用 inserted 表限定本次新增数据，避免更新历史数据。


五、相比普通手工传值的优势

1. 不需要实施人员记住每张表和字段。
2. 自动识别大部分业务链路。
3. 一条规则可跨多张单据。
4. 支持单头与单身双向取值。
5. 支持不同来源和混合来源。
6. 支持一次配置多个字段。
7. 每个目标表只保留一个工具触发器。
8. 后续增加字段时自动合并旧触发器。
9. 支持字段替换和同字段追加。
10. 自动阻止重复追加相同值。
11. 有预览、备份、字段校验和事务保护。
12. 可按不同数据库重新生成链路注册表。
13. 便携版和安装版都可独立运行。

类型覆盖：

- 文本

其他验证：

- 多字段映射
- 同源和异源字段

七、备份与旧备份清理

所有备份入口统一调用同一个函数：

backupDatabaseWithCleanup()

调用入口：

1. 正常执行传值前
2. 建立触发器前
3. 删除触发器前

统一流程：

1. 生成带时间戳的 .bak 路径。
2. 执行数据库备份。
3. 无论本次备份成功或失败，都检查旧备份。
4. 删除当前备份目录中修改时间超过 3 天的 .bak。
5. 返回备份结果和清理数量。

清理范围：

- 当前配置的备份目录
- 只处理直接位于该目录下的 .bak
- 不扫描子目录

备份失败不会阻断传值或触发器操作，但会写入调试日志。


八、当前边界和风险

1. 工具深度依赖当前 ERP 的表结构、字段说明和来源编码规则。
2. 来源代码没有明确含义时，自动判断仍可能不足。
3. 17 张无业务说明的系统内部表不进入前台单据字典。
4. 不会为没有业务关系的任意两张表强行建立链路。
5. 直接操作数据库会绕过 ERP 前端部分业务校验。
6. 触发器可能与 ERP 自带触发器冲突。
7. ERP 升级后表结构、字段或触发器可能变化。
8. 数据库必须为操作账号提供备份和触发器权限。
9. 大数据库备份会增加磁盘 I/O 和备份时间。
10. 正式写入前仍应在测试账套完成业务验收。


九、是否有创新性

有。

创新点不是简单写 SQL，而是：

从人工查找字段和编写规则
升级为
基于 ERP 元数据和业务链路图的自动数据映射

它把以下孤立工作合并成一个流程：

- 元数据扫描
- 来源代码识别
- 业务链推导
- 路径去重
- SQL 生成
- 多字段触发器
- 备份与安全执行

这对 ERP 实施、二次开发、数据修复和非标字段联动具有实际价值。


十、是否可能颠覆行业

客观判断：

当前不能颠覆整个 ERP 行业。

当前有机会颠覆或显著优化：

ERP 非标传值、字段自动联动、历史数据补齐、触发器管理和实施交付环节。

要成为行业级产品，还需要：

1. 支持多个 ERP 厂商和不同数据库结构。
2. 建立可维护的来源代码字典。
3. 提供映射审批、变更审计和版本回滚。
4. 支持 API 与数据库双通道。
5. 提供更完整的业务规则验证。
6. 支持多用户、权限和集中管理。
7. 建立行业规则库并持续积累。
8. 证明长期运行不会污染业务数据和触发器。


十一、未来产品方向

Momo传值助手可以继续演进为：

企业业务数据映射与自动联动平台

可扩展能力：

1. 单据字段自动联动
2. 历史数据批量修复
3. 数据质量检查
4. 非标接口替代
5. 数据迁移
6. 业务链追溯
7. 映射规则审计
8. 触发器生命周期管理
9. 多 ERP 适配
10. 多用户和集中部署


十二、结论

Momo传值助手已经从一个单点传值工具，发展为具备元数据识别、业务链推导、安全 SQL 生成、多字段触发器、增量合并和备份保护能力的 ERP 数据联动工具。

它的现实价值明确，尤其适合 ERP 实施和运维中的重复性传值工作。

它目前不是通用 ERP 平台，也不应宣传为可以无条件替代所有业务接口。

最合理的定位是：

数据库结构感知的 ERP 业务链路与字段联动自动化工具

继续保持安全、可验证、可回滚和规则可治理，比单纯增加功能按钮更重要。
