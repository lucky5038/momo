# N-B助手 新旧版本对比（2.2.101 → 2.9.0）

> 对比对象：**基线 2.2.101**（可用发版版本，tag `v2.2.101-refactor-base`）与 **2.9.0**（本轮重构完成版，commit `3370d33`）。
> 结论先给：**功能没变，界面换了骨架；后端一行业务逻辑没动，前端从「一个 150KB 的内联 HTML」变成「22 个带类型的源文件」。**

---

## 一、一句话看懂差别

| 维度 | 旧版 2.2.101 | 新版 2.9.0 |
|---|---|---|
| 界面怎么来的 | `public/index.html` 单文件，构建时被 `regen-inline.js` 塞进 `public_inline.js`，运行时整段 HTML 字符串吐给窗口 | `renderer/src` 用 Vue3 + Vite + TS 写成组件，`vite build` 出 `dist`，后端静态服务它 |
| 改界面的成本 | 改 2843 行里的某一段，改了就得重跑内联 + 重启 | 改对应 `.vue`，Vite 热更新毫秒级 |
| 界面文件规模 | 1 个文件 2843 行 / 150,778 字节，其中 CSS 50,800 字符、JS 约 74,500 字符 | 22 个文件 3515 行，最大单文件 806 行 |
| 样式怎么组织 | 5 套 `:root` 主题块层层覆盖（quiet carbon → cyber neon → geek deep-space → slate），实际只有最后一套生效，前 4 套是死代码 | 1 套「纸墨」主题，所有颜色/字号/圆角/阴影集中在 `styles/paper.css` |
| 组件复用 | 无（DOM 手动 `innerHTML` + 事件绑定） | 有（侧栏、顶栏、列下拉、状态提示、错误处理都是组件/组合式函数） |
| 错误处理 | 只看 HTTP 状态码，`200 + {ok:false}` 当成功 | 统一 `ApiError`，`200 + ok:false` 也抛错，带后端 hint |
| 打包后加载哪个界面 | 只能加载内联旧界面 | 自动判断：有 `renderer/dist` 就加载新界面，没有才回落旧界面 |

---

## 二、技术栈换代

| 层 | 旧 | 新 | 换来的东西 |
|---|---|---|---|
| 视图 | 原生 DOM + 字符串拼接 | Vue 3 `<script setup>` + 单文件组件 | 状态驱动、改一处不用找 DOM、组件可复用 |
| 构建 | 自写 `tools/regen-inline.js`（把 HTML 塞进 JS 字符串） | Vite 6（`vite build` 0.8 秒出包） | 真正的模块化、按需 chunk、产物 gzip 后仅 57KB |
| 类型 | 无 | TypeScript 5.6（`vue-tsc --noEmit` 0 错误） | 列名、接口字段、枚举值写错编译期就报 |
| 状态 | 全局 `state` 对象 + 手动同步 DOM | Pinia（`stores/app.ts`、`stores/crossfill.ts`） | 单一数据源，跨页共享字典有失效机制 |
| 路由 | 6 个 `data-page` 区块手动显隐 | Vue Router（hash 模式，`/run` `/triggers` …） | 前进后退可用、深链可用、页面按需加载 |
| 请求 | 各处 `fetch` 手写 | `api/client.ts` 统一封装 | 错误、hint、超时、`ok:false` 一处处理 |
| 打包 | electron-builder 只带 `public_inline.js` | 多带一个 `renderer/dist`（187KB） | 包体只增 187KB，换来整套工程化 |

## 三、代码结构对比

**旧版（2.2.101）**
```
source/
├─ public_inline.js          158KB（构建产物，人不可读）
└─ src/
   ├─ public/index.html      2843 行 / 150KB：样式 5 套 + 6 个脚本块全在里面
   ├─ app.js                 1962 行：HTTP 服务 + 32 个接口
   ├─ sqlgen.js               919 行：SQL 生成
   ├─ cleaning.js             Excel 模板解析 / 校验 / 生成 XLS
   ├─ chain.js / dicts.js / field-dict.js / source-dict.js
   ├─ main.electron.js       Electron 主进程
   └─ preload.js             桥接（另存为 / 打开目录）
```

**新版（2.9.0）**
```
source/
├─ renderer/                 ← 新增，前端工程
│  ├─ index.html  vite.config.ts  tsconfig.json  package.json
│  └─ src/
│     ├─ main.ts / App.vue           应用入口 + 外壳（侧栏 + 顶栏 + 内容区）
│     ├─ router/index.ts             6 个模块路由 + 404 兜底
│     ├─ config/app.ts               版本号 + 模块清单（侧栏与路由共用一份）
│     ├─ styles/paper.css            唯一主题：颜色/字号/圆角/阴影 token
│     ├─ styles/base.css             reset + 纸纹背景 + 滚动条
│     ├─ api/client.ts               统一请求封装（含 ok:false 判定）
│     ├─ api/{crossfill,cleaning,triggers}.ts  各模块类型与接口
│     ├─ stores/{app,crossfill}.ts   连接状态/字典代次、跨表带值状态机
│     ├─ composables/useStatus.ts    页面状态提示（收敛了 4 份重复实现）
│     ├─ lib/error.ts                错误文案统一
│     ├─ components/AppSidebar.vue   侧栏（6 模块 + 品牌 + 版本）
│     ├─ components/AppTopbar.vue    顶栏（标题/连接状态/账套/重新连接）
│     ├─ components/ColumnCombo.vue  可搜索列下拉（键盘 + 无障碍）
│     └─ views/                      跨表带值 / 触发器 / 设置 / 清洗 / 占位说明页
└─ src/                      ← 后端保持原样，只改了 3 处（见下）
```

**后端改动（全部是新增能力，不动业务逻辑）**

| 文件 | 改动 | 原因 |
|---|---|---|
| `src/app.js` | +39 行：新增 `serveRenderer()` 静态服务分支（MIME、防目录穿越、未知路径回落 `index.html`）+ electron-builder `files` 加 `renderer/dist/**/*` | 让打包后的 exe 能加载新界面；没有 dist 自动回落旧界面 |
| `src/main.electron.js` | +52/−16：`useNewUI` 判断、浅色标题栏（`titleBarStyle:'hidden'` + `titleBarOverlay`）、开发态 `NB_RENDERER_URL` 分支、模板库目录可外部指定 | 新界面要自绘标题栏才能和纸墨主题同色；开发版要能挂 Vite |
| `src/public/index.html` | **零改动** | 旧界面原样留着当回退，随时可发版 |

## 四、这一版解决了什么问题

### 1. 架构类（决定以后能不能继续长大）
- **界面改不动**：旧版所有样式和脚本挤在一个 HTML 里，改一处要读 2843 行。现在按模块拆成 `.vue`，改动范围可预测。
- **5 套主题叠在一起**：`:root` 从 11 行叠到 612 行，前 4 套（quiet carbon / cyber neon / geek deep-space）全是死代码。现在只有 1 套「纸墨」token。
- **没有组件化**：列下拉、状态提示、错误文案在旧版是 4–6 份复制粘贴。现在各有唯一实现。
- **JS 是「一次性」的**：旧版 74KB 内联脚本没有类型、没有模块边界。现在 TS 严格模式，`vue-tsc` 0 错误。

### 2. 数据安全类（会写错库的那种）
- **切账套后字典不失效**：旧逻辑（以及我 2.4.2 初版）切库后仍能选到旧库的列，可能把值写进新库。现在有 `generation` 代次，切库/测试连接/重连后自动作废重拉。
- **清洗「条件必填」失效**：`requiredIf` 没回传，后端 `cleaning.js:1035-1040` 的依赖判断整条不生效。已修。
- **动作并发**：连点会并发预览/生成/切库，互相覆盖。现在每页单动作串行 + 序号守卫，只认最后一次结果。

### 3. 假成功类（最容易坑人的）
- **`200 + {ok:false}` 当成功**：测试连接失败、跨表带值失败都可能显示成功。现在统一抛错并显示后端原因。
- **顶栏状态不真实**：原来只看 config 文件。现在「重新连接」走 `/api/meta` 真探活，失败给出具体原因（本轮验证时 SQL 不可达，页面如实显示 `Failed to connect … in 4000ms`，这在旧版会显示「已就绪」）。

### 4. 体验细节类
- 执行/清除确认框补账套、备份目录、非空值数量。
- 预览只回 50 行样本时明确提示「只列前 N 行，实际写入 M 行」。
- 空结果解释「数值 0 也算已有值」。
- 顶栏「刷新状态」→「重新连接」，语义更准。
- 触发器操作后的成功提示不会被刷新清掉。

### 5. 可维护性类
- 删除死代码：`version`/`connText`/`--adv-title`/`ColumnCombo` 死防御值/6 个无调用方 API 方法/`as unknown as` 泛型逃逸。
- `triggerBlocked` 判断时机修正（原实现清空 srcId 后才判断，恒为 false）。
- 所有计时器（300ms 记忆、5s 删除确认、1.4s 定位高亮）在卸载时清理。
- 无障碍：`label for`、`role=status aria-live`、`combobox` 键盘（↑↓/Enter/Esc）。

### 6. 体积类
- 应用图标 219KB（512×512 原图）→ 11.5KB（64×64）。
- 前端产物 187KB（gzip 后 62KB）。
- 仓库删掉 13 个一次性产物（审计 CSV、临时 CDP 脚本）。

## 五、没有变的东西（重要）

- **后端传值引擎**：`sqlgen.js` / `chain.js` / `cleaning.js` / `dicts.js` / `field-dict.js` / `source-dict.js` **一行没动**。
- **32 个 `/api/` 接口契约**：路径、请求体、返回体全部保持，新前端只是换了调用方。
- **业务规则**：960–995 自定义列限制、强制覆盖先置空、合并显示优先、触发器临时禁用与回滚、模板 sha256 判重等，全部照旧。
- **旧界面**：`public/index.html` 原样保留，作为回退路径。
- **发版基线**：`2.2.101` 仍然可发版；新版尚未打包。
